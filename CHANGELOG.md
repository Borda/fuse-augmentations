# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Versions below `0.12.0` are `dev0` snapshots, each cut from its own `bump vX` commit's tree. `0.1.0.dev0` through `0.9.0.dev0` were batch-uploaded to PyPI together on 2026-07-11, catching up nine commits at once; `0.10.0.dev0` followed separately on 2026-08-02. `0.11.0.dev0` was never published to PyPI — only `0.12.0` and later exist there next to it. `0.12.0` is the first stable release and the first cut from a `vX.Y.Z` tag.

## [Unreleased]

### Added

- `mask_fill` on Compose and its factories supplies a scalar auxiliary-mask border independently of image `fill`, including ignore labels `255` and `-1`. Values are validated against the mask dtype; nonzero fill uses coverage sampling to preserve in-bounds values.

- `augment_detection_batch` packs per-image `boxes`/`labels` through the dense box pipeline, clips and filters using one survival mask, and keeps optional `area`, `iscrowd`, and `image_id` aligned. A real Faster R-CNN training-step regression exercises this boundary.

- `SyntheticIterableDataset` accepts explicit `rank`, `world_size`, and immutable `epoch`; `num_images` is per rank. Recreate dataset/loaders per epoch with `persistent_workers=False`; topology-independent replay and persistent-worker epoch updates remain unsupported.

- Exact geometric operations and standalone deterministic letterbox expose their actual-call pixel-centre matrix through `return_matrix=True`. Coordinate helpers can recover predictions; the image `inverse()` scope remains limited to one supported fused affine/projective segment. Exact operations now share one sampled parameter set for pixels and matrices; seeded output can differ from the former singleton native shortcut.

- The multi-target path accepts channel-last NumPy images. `Compose(..., data_keys=["input", "bbox_xyxy"])` previously required tensors for every target, so a caller holding an Albumentations-shaped `(height, width, channels)` array and an `(num_instances, 4)` box table had to convert both by hand before the call and convert the results back afterwards. Passing arrays now normalises the image through the same `NumpyToTorchConverter` the `output_backend` path uses, adds the batch axis coordinate targets need, and returns every result in the caller's own layout — a `(height, width)` grayscale image comes back without a trailing singleton channel axis, and unbatched boxes come back unbatched. A NumPy image comes back in the dtype it was passed in: where the call normalises internally, the `uint8`/`uint16` scaling is undone on the way out, so the dtype does not depend on which internal path ran. Tensor and array inputs may not be mixed within one call: an array auxiliary target alongside a tensor image raises `TypeError`, since an unbatched array and a batched tensor have no common batch-dimension reading.

- `rotation_p` and `scale_p` on `Compose.from_params` (keyword-only): per-sample application probabilities for the geometric ranges, matching the `hflip_p`/`vflip_p` convention already on that surface. Previously only the flips could be made probabilistic from `from_params` — the geometric kwargs were built with a hardcoded `prob=1.0`, so expressing "rotate half the batch" meant dropping to `from_config`/`specs=`, where per-op `prob` has always been available. Both default to `1.0`, which is the historical behaviour: with the defaults in place every range still shares a single direct-parameter transform, so the number and order of generator draws is unchanged and an existing seeded pipeline produces bit-for-bit identical output. A probability below one moves that range into its own transform so its gate is drawn independently of the rest of the geometry. `scale`, `scale_x` and `scale_y` share `scale_p` because they describe one scaling of the same sample; use `specs=` for finer control. Values outside `[0, 1]` raise at construction, matching the bound `TransformSpec` already enforces, and passing either alongside `specs=` raises like every other keyword parameter.

- Albumentations `RandomSizedCrop` is registered as a crop-resize op, so it is planned as a `CropResizeSegment` and routes masks, boxes and keypoints through the crop like `RandomResizedCrop` already did. The two share `_BaseRandomSizedCrop`, hence the same `size` attribute and the same `crop_coords` result the adapter already extracts; before this, only `RandomResizedCrop` was in the registry and `RandomSizedCrop` fell back to a passthrough barrier, where auxiliary targets are not routed at all. `RandomSizedBBoxSafeCrop` is deliberately **not** registered and stays a barrier: it derives its crop window from the sample's bounding boxes, while crop parameters are sampled against a dummy image the caller's boxes never reach, so a registered version would choose a window that ignores the instances it exists to preserve — with every shape still lining up and nothing raising.

- `execution="auto"` as a third accepted value, alongside `"cv2"` and `"torch"`, resolving per call by a fixed documented rule: host data warps in OpenCV, accelerator data in `grid_sample`. It is never the default and never changes what an already-pinned engine does. Choosing it opts out of bit-reproducibility across environments, since the engine becomes a function of where the tensors live rather than of the recorded configuration -- so the new `resolved_execution` property reports which engine the most recent call actually used, and is `None` until one has warped something. A pipeline pickled with `"auto"` re-resolves on unpickling rather than freezing the engine it picked, so a `DataLoader` worker routes for its own data. The measurement that justifies the rule is `experiments/bench_rfdetr_shape.py`: on the host, `grid_sample` runs five to sixteen times slower than `warpAffine` on a detection-shaped step, while on an accelerator it is the only engine that can run at all.

- A multi-target call on NumPy input stays in NumPy/cv2 space. Declaring `data_keys` used to force the tensor path: the image was normalised to float32 `(batch, channel, height, width)`, warped, and converted back, costing three full-image layout copies and a warp over four times the bytes -- work native Albumentations never does, and the reason a detection-shaped step measured 0.48x its speed at 1024 px. Auxiliary targets never required any of it; coordinate tables are small enough to route as tensors for free, and the NumPy image path already composes the same fused matrix. The image now stays in the caller's dtype and layout while masks, boxes, keypoints and rotated boxes route through that matrix, landing bit-identically to the tensor path. The same detection step now measures 1.05x native Albumentations at both 640 and 1024 px, and 2.9x on a four-op chain, where fusion has something to fuse. A pipeline whose chain holds a crop, an exact affine or an opaque passthrough cannot expose a matrix per segment and silently keeps the tensor path, as does `execution="torch"` -- execution is a reproducibility axis fixed at construction and must not change because the input happened to be an array.

- A multi-target pipeline accepts the image positionally alongside auxiliary keywords — `pipe(image, bboxes=...)` — returning the same dict as the all-keyword form. Only that one mixed shape is accepted; two or more positional arguments combined with keywords still raise, because once some data keys are passed by name there is no unambiguous mapping of the remaining positional arguments onto the rest.

### Changed

- **Bounding-box numerical migration:** xyxy/xywh use pixel-edge extents `[0, W] x [0, H]`. Their helpers convert pixel-centre image matrices internally; full-frame boxes now survive flips without a one-pixel shift. Keypoint and rotated-box centre conventions are unchanged; convert rbox envelopes by `+0.5` when comparing against edge-space AABBs.

- NumPy auxiliary masks retain label values and dtype during layout conversion. Integer masks now reject bilinear sampling consistently with tensor masks; image normalization is unchanged.

- A fused affine segment on an accelerator now samples its per-transform parameters and builds their matrices on the host, then moves the whole chain across in one transfer. Adapters construct parameter tensors with an explicit `device=`, so sampling on a device issued a separate host-to-device copy per parameter — roughly ten per call for a five-transform chain. Profiled on MPS that was the call: 40% in `Tensor.to` and 26% in `torch.tensor`, with matrix composition 86% cumulative, against about 1% in `affine_grid` and a `grid_sample` that did not reach the top of the profile. The warp fusion exists to save was not what the call spent its time on. The same five-transform chain measures 1.51x faster on MPS at batch 8. CPU is untouched by construction — the host is already the sampling device there — and every RNG draw stays exactly where it was, including the per-sample activation draws, which still run on the image's device against the same generator. Kornia's `RandomRotation90` opts the whole chain back out, because its matrix build falls back to a `torch.randint` whose stream is selected by the sampling device; a chain containing it keeps sampling on the image's device. Accelerator results shift by up to ~3e-05 in the composed matrix, since the trigonometry now runs in host float32 rather than device float32 — a change in the direction of the CPU path, which composed those same matrices all along.

- Under `execution="torch"`, an image-only Albumentations crop routes through `CropResizeSegment` instead of falling back to a native passthrough. The fallback exists to keep the crop bit-exact by running Albumentations' own crop, and that trade only pays while the rest of the chain is bit-exact too: on the torch path the image is already warped by `grid_sample`, so the native crop buys parity the chain has given up while still costing a device-to-host round trip for the whole batch on every call. Measured on MPS against the passthrough the routed crop runs 0.83x at batch 8, 1.17x at 32 and 1.39x at 64 — a win at training batch sizes and still a loss at small ones. `execution="cv2"` and `"auto"` are unchanged: `"auto"` resolves per call, so the device is unknown when segments are built, and its documented common case is host data on cv2 where the native crop is right. Declaring any auxiliary target still routes the crop on every engine, as before.

- The four-corner AABB reduction in `transform_bbox_xyxy` uses `torch.amin`/`torch.amax` instead of `Tensor.min(dim=)`/`Tensor.max(dim=)`. The indexed variants also compute an argmin and dispatch a parallelised reduction whose thread-pool cost is roughly 38 us regardless of tensor size; on the `(batch, instances, 4)` corner axis that made four calls 43% of the entire fixed per-call cost of a detection-shaped step, which fell from 0.40 ms to 0.15 ms. Forward values are unchanged, NaN included. Two backward-pass behaviours do change, and neither is relied on by any target modality -- boxes are input data and the documented differentiable target is the soft mask: tied corners, which every axis-aligned box has, now split the subgradient evenly instead of routing it all to the lowest index, and a NaN corner poisons every gradient rather than selecting the NaN's own index.

- The residual difference between the two entry points' composed matrices is now bounded and tested rather than unexamined. The NumPy path multiplies the float64 matrices Albumentations produces; the adapter path rounds each factor through float32, because matrices ride alongside tensors and MPS has no float64. A multi-op chain therefore accumulates up to one float32 epsilon (1.19e-07) of difference between the two, which moves a 1024-pixel coordinate by 1e-04 of a pixel. Rounding the NumPy path down to match was tried and reverted: it cost bit-exactness against native Albumentations on the `uint8` single-op parity rows, which is the more valuable of the two agreements. `TestEntryPointAgreement` now asserts the bound, so a larger divergence -- different sampled parameters, or a different accumulation order -- fails rather than hiding inside a tolerance.

### Fixed

- The NumPy image path draws one Bernoulli activation per transform whatever its probability, matching the tensor path. It previously skipped the draw when the probability was exactly `0.0` or `1.0`, which gives the same activation but leaves the global `numpy.random` stream in a different place: a caller who seeded once and switched between array and tensor input got different sampled geometry from an identical pipeline, with nothing in the configuration explaining it. A seeded run whose chain contains a `p=1.0` or `p=0.0` transform and which called the NumPy path will sample differently than before this change; the two entry points now agree, which is the property worth having.
- Auxiliary-target geometry no longer inherits the image's dtype. The composed matrix that places boxes, keypoints and rotated boxes was cast to `image.dtype` before routing, so a float16 image rounded the affine coefficients positioning its own targets -- 0.011 px on a 17-degree rotation -- and an integer image would have truncated them to whole pixels, with every shape still lining up and nothing raising. Geometry now routes in float64 for a float64 image and float32 for everything narrower, which is what the image warp and the public matrix already did.
- A raw NumPy image on the multi-target path no longer crashes with a shape-unpacking error. `_forward_kwargs_dict` built its argument tuple with a `cast` to the tensor type, which is a typing assertion with no runtime effect, so the untouched `(height, width, channels)` array flowed through to a four-way `batch_size, num_channels, height, width = image.shape` unpack inside the fused affine segment and raised there rather than at the call. Nothing exercised raw NumPy plus an auxiliary target through the `execution="cv2"` engine, which is why the combination stayed broken; the new integration tests cover it on both engines and compare the results against the equivalent tensor call so the two entry points cannot drift apart again.

## [0.12.0] - 2026-09-02

First release published from a tag rather than a batch upload, and the first non-`dev0` version: every `0.x` below shipped only as a `dev0` snapshot, which a `>=X.Y,<X.Y+1` pin cannot resolve without `--pre`.

### Added

- `keypoint_flip_index=` on `Compose`, `Compose.from_params` and `Compose.from_config`: a caller-supplied keypoint pair permutation applied to the `"keypoints"` target whenever the composed transform reverses orientation, so a mirrored image's left and right landmarks swap identity along with their coordinates. **When it fires is read off the sign of the composed matrix's determinant**, never off whether a flip transform appears in the pipeline: after fusion the mirror is part of a larger matrix and is no longer a discrete op, two mirrors compose back to a rotation that must *not* swap, and a rotation past 90 degrees looks like a flip while being none. Every routing path applies it, including the two that never build a warp grid — the exact-flip route (where the swap is gated on exactly one of the horizontal and vertical flips being active, since two perpendicular mirrors are a half turn) and the D4 fast path, which applies a pure flip by tensor reversal and skips `grid_sample` entirely; a permutation wired only into the interpolating route would have left those images mirrored with unswapped labels and no shape error anywhere. The pair table itself is dataset schema and stays with the caller; the package validates only that it is a permutation of `range(len(flip_index))`, because a table that repeated or dropped a slot would duplicate one landmark and silently delete another. `orientation_reversed()` and `permute_keypoint_pairs()` expose the same decision outside the pipeline. `None` (the default) leaves the keypoint axis in input order. See "Keypoint pairs under a mirror" in `docs/guides/auxiliary-targets.md`.
- Rotated boxes are a first-class target modality: the `"rboxes"` data key carries `(B, N, 5)` `(cx, cy, w, h, theta)` (radians) and is routed by every path that already routed plain boxes — fused affine, the exact-flip path, crop-resize, letterbox and the Albumentations tensor path. Public helpers `rboxes_to_corners`, `corners_to_rboxes`, `transform_rboxes`, `mirror_rboxes`, `shift_rboxes` and `rbox_envelopes` expose the same arithmetic outside the pipeline. A general affine does **not** map a rectangle to a rectangle — only a similarity does, and shear sends a rectangle to a parallelogram that no `(cx, cy, w, h, theta)` describes — so the transport expands each box to the four corners the warp actually moves, maps those, and re-fits a box to them, with no single vertex deciding the result (centre from the vertex centroid, each extent the mean of its pair of opposite sides, direction the mean of that pair's antiparallel edges). Under rotation, uniform scale, translation and mirroring the fit is exact; under a shear of angle `s` the fitted corners sit `(h / 2) * sqrt(tan(s)**2 + (1 - 1/cos(s))**2)` from the warped ones, where `h` is the extent across the shear — the familiar `h * sin(s / 2)` is the first-order form of that and, measured, understates the true value from the third order on, so it is an estimate rather than a bound. **No canonical form is imposed**: no `w >= h` swap, no angle range, because the long-edge convention is one reading of the literature among several and belongs with the assigner, loss and evaluation kernel that share it; `transform_rboxes`, `mirror_rboxes` and `shift_rboxes` take an optional `canonicalize=` callable so a caller applies its own in one place. Mirroring reflects about `(width - 1) / 2`, this package's `align_corners=True` flip axis rather than the `width / 2` an extent-convention implementation uses, and the exact-flip and fused-matrix paths were made to agree parameter for parameter (both return `pi - theta` for a horizontal mirror) rather than only geometrically. Clipping a rotated box to the canvas is deliberately **not** provided — the clipped shape is a polygon, not a rotated box — so `rbox_envelopes` bridges to `clip_bbox_xyxy` and `instance_keep_mask` for the survival decision instead. See "Rotated boxes" in `docs/guides/auxiliary-targets.md`.
- `letterbox=(height, width)` on `Compose.from_params` (a single `int` for a square), with `allow_upscale=`, plus the public `letterbox_matrix()` / `letterbox_geometry()` / `LetterboxGeometry` that expose the same fit as data. Content is scaled by one ratio `r = min(height_out / H, width_out / W)` and the slack is padded with `fill`, so the map is a pure scale plus translation `[[r, 0, pad_left], [0, r, pad_top], [0, 0, 1]]` and inverts exactly through `inv3x3` — a prediction made on the letterboxed canvas returns to source coordinates with no resampling, which is what makes the letterbox usable as an inference preprocessor rather than only a training resize. The geometry is computed from sizes alone (unrounded `r`, content size `max(1, round(size * r))`, pads `(out - new) // 2`), so an evaluation loop holding only the original and letterboxed sizes can recompute and invert it; the integer floor-halved pads put the extra pixel of an odd slack on the right or the bottom, matching a resize-then-pad implementation pixel for pixel. The op is classified `CROP_RESIZE_FIXED`, so it reuses the existing shape-changing machinery: standalone it becomes a `CropResizeSegment`, and after a geometric run — interpolating or an exact flip — it fuses into a `_FusedGeoCropSegment`, one composed matrix and **one** `grid_sample` straight from the source canvas to the letterboxed one, with `return_matrix=True` handing back the whole chain rather than the letterbox alone. It is placed after the geometry and before any `brightness`/`contrast`: the crop-resize category is a reorder barrier, so a colour op buffered ahead of it would be flushed between the geometric run and the letterbox and split the fusion — which also means a colour op in the same call acts on the pad region. `allow_upscale=False` caps the ratio at `1.0`, padding rather than magnifying. Backend-free mode only; `backend=` raises instead of accepting and ignoring it. See "Letterbox with an exact inverse" in `docs/guides/configuration.md`.
- `instance_keep_mask()` and `clip_bbox_xyxy()` in `fuse_augmentations.targets` (both re-exported at package level): the post-warp instance-survival rule a detection recipe needs after a geometric warp pushes instances off the canvas. `clip_bbox_xyxy` clamps `xyxy` boxes to the `[0, width] x [0, height]` canvas *extent* — the area convention the visibility ratio needs, not the `width - 1` distance between outer pixel centres. `instance_keep_mask(boxes, clipped_boxes, min_size=, min_visibility=)` keeps an instance whose clipped box is at least `min_size` on both axes and retains at least `min_visibility` of its unclipped area; a box whose unclipped area is zero is given visibility zero rather than dividing by it. Both thresholds are the caller's — they are a training recipe's numbers, and the defaults of `0.0` deliberately drop nothing rather than encoding a sensible-looking minimum. The return value is the **mask**, never a filtered box tensor, and that is the whole point: labels, keypoints, rotated boxes, polygon rings and per-instance flags all share the instance axis, only the caller holds all of them, and a helper returning filtered boxes would leave a pipeline whose boxes and keypoints describe different instances while every shape still lines up and nothing raises. Accepts `(..., 4)`, so both a batched `(B, N, 4)` and a per-sample `(N, 4)` table work, and the mask is always the full input length in input order. Not to be confused with `clip_policy`, which decides when a fused *colour* chain clamps to `[0, 1]`; the names are close and the concepts share nothing. See "Deciding which instances survive a warp" in `docs/guides/auxiliary-targets.md`.
- `fill=` on `Compose`, `Compose.from_params` and `Compose.from_config`: a constant value written into the region outside the source canvas, in the image's own value range — `114` for a uint8 grey, `114 / 255` for the same grey as float, nothing rescales it. A scalar fills every channel, a sequence one channel each. It is a parameter rather than a `PaddingMode.CONSTANT` member because `PaddingMode` is an `IntEnum` ordered by sampling quality (`REFLECTION > BORDER > ZEROS`, asserted in its own doctest) and a constant colour has no position in that ordering; the parameter form also composes with a per-channel value, which an enum member cannot carry. `fill` needs a constant border to replace, so it requires `padding_mode="zeros"` (the default) and raises against `"border"`, `"reflection"` and `"per_transform"` instead of being silently ignored on part of the pipeline. The fill applies to the **image** only: a routed mask keeps its zero padding, because outside the canvas a mask means "no instance" rather than a colour. `grid_sample` has no constant padding mode, so the torch warp subtracts the fill, samples against the zero border and adds it back — an out-of-canvas sample returns exactly the fill and a boundary sample blends interior with fill the way a constant border does — while the cv2 warps pass it as `borderValue`, built out to the image's channel count (cv2 reads a bare number as `Scalar(v, 0, 0, 0)`, which would fill only the first channel). Both the batched `grid_sample` path and the batch-size-dependent B=1 CPU cv2 fast path inside the same segment class produce the same border, which is pinned by test rather than assumed. cv2's `borderValue` carries four components, so a per-channel fill on an image with more than four channels raises for the cv2 path and points at `execution="torch"`. `fill=None` (the default) leaves every warp call and its output unchanged. See "Constant border colour" in `docs/guides/configuration.md`.
- `generator=` on `Compose`, `Compose.from_params` and `Compose.from_config`: a caller-owned `torch.Generator` drives every draw the pipeline itself makes — the thirteen geometry and colour parameter draws of the direct-parameter engine, and the per-transform Bernoulli probability gates on the fused affine, exact-flip, geo-crop and fused-colour segments. The point is isolation rather than seeding as such: with the global stream, any other component drawing between two pipeline calls changes what the pipeline samples, so a seeded augmentation could not be replayed inside a process it did not fully own. `generator=None` (the default) keeps the historical global-stream calls untouched on every device, so existing pipelines are bit-for-bit unchanged. The generator's device need not match the tensors': the draw happens on the generator's device and is copied across, so one CPU-seeded configuration can drive a CUDA or MPS pipeline, which `torch` itself refuses. Supported on the direct-parameter engine only — `from_params(backend=None)` and `backend="native"`. Kornia, TorchVision and Albumentations sample inside their own libraries (Kornia's `generate_parameters`, Albumentations' `py_random` and `np.random`, TorchVision's parameter hooks), and no `torch.Generator` reaches any of them, so passing one together with backend transforms raises at construction instead of falling back to the global stream — a fallback there would report a reproducibility the run does not have. Pickling a pipeline (what a `DataLoader` worker receives) carries the generator's state as of pickling, so workers must be seeded per worker rather than sharing one restored stream. See "Caller-owned randomness with `generator=`" in `docs/guides/reproducibility.md`.

### Fixed

- A pipeline built with `generator=` now pickles on every supported torch version. `torch._C.Generator` is unpicklable on older torch, including the 2.2 floor this package supports, so `pickle.dumps(pipe)` raised `TypeError: cannot pickle 'torch._C.Generator' object`, exactly at the `DataLoader` worker boundary a seeded pipeline has to cross. The pipeline and its generator-driven segments now serialize the generator's device and byte state instead of the object, and the pipeline rebinds every segment to the single restored instance on unpickling — separate copies would sit at the same state and replay one another's numbers rather than advancing one shared stream. The restored stream resumes where the pickled one stood, unchanged from the documented behaviour on torch versions that could already pickle a generator.
- `_build_mixed_segments` (the mixed-backend planner path) forwards `fill` and `keypoint_flip_index`, which it previously took no parameters for at all: a `FusedCompose` routed through the mixed-backend branch silently dropped both — the zero border replaced `fill`, and mirrored images kept unswapped keypoint identities — even though `pipe.fill`/`pipe.keypoint_flip_index` still read back correctly.

### Changed

- **The half-pixel convention is now measured and pinned, and stays a single convention.** Sampling has always run with `align_corners=True` against the normalization sandwich derived for that same flag, which means the *pixel-space* map is the one an `align_corners=False` implementation (TorchVision, Albumentations, most YOLO data pipelines) produces for the same matrix — the convention cancels between the sandwich and the sampling flag, and only the normalization into `[-1, 1]` ever carried it. `tests/test_unit/affine/test_coordinate_convention.py` now warps against an independently constructed `align_corners=False` reference for integer, half- and quarter-pixel shifts, up- and downscales, rotation, a non-square canvas, and — through `normalize_matrix_io` — differing input and output sizes, matching to float32 rounding in every case, so a matrix transfers in either direction unchanged. The same file pins the co-location invariant across all three transport paths: a keypoint placed on a bright pixel still sits on that pixel after the warp (coordinates are multiplied by the pixel matrix with no normalization step anywhere), and a mask marking it still marks it (masks resample on the image's own grid). Two residuals are pinned rather than left to be discovered: `padding_mode="reflection"` genuinely differs (`align_corners=True` reflects about outer pixel centres, OpenCV `BORDER_REFLECT_101`; `False` reflects about outer pixel edges, `BORDER_REFLECT`), and a canvas thinner than two pixels on an axis is refused by name, since the `True` normalization divides by `L - 1`. No `align_corners` parameter is added: outside reflection padding it would change nothing measurable, and a flag that alters one padding mode while claiming to select a coordinate convention is worse than the documented behaviour. See "Half-pixel convention" in `docs/guides/configuration.md`.
- **Releases are now cut from a tag, not a batch upload.** `.github/workflows/release.yml` publishes on a `vX.Y.Z` tag push only — never on a branch push — checks the manifest, builds the distributions, verifies that the tag and `__about__.__version__` agree before anything is uploaded, runs `twine check`, and publishes through PyPI Trusted Publishing (`id-token: write`, no stored API token), gated behind the `pypi` GitHub environment. Pre-release tags (`a`, `b`, `rc`) go through the same path; a `dev` version deliberately has none, since a `>=X.Y,<X.Y+1` pin cannot resolve one without `--pre`. `.github/CONTRIBUTING.md` gains a "Cutting a release" section documenting the three manual steps (close the changelog, set `__version__`, tag and push) the workflow then verifies.

## [0.11.0.dev0] - 2026-09-02

### Added

- `fuse_augmentations.data.animals.AnimalShape` adds 12 animal side-profile silhouettes — `duck`, `elephant`, `giraffe`, `fish`, `rabbit`, `camel`, `eagle`, `penguin`, `whale`, `kangaroo`, `flamingo`, `crocodile` — fixed outline tables loaded in that same module. Unlike the geometric shapes, none is rotationally symmetric, so every silhouette carries real orientation under any rotation angle; they were added as a basis for future keypoint annotation work, where a symmetric outline makes a landmark's identity ambiguous under rotation. `SyntheticConfig` gains a `shapes: tuple[Shape, ...]` field (default `DEFAULT_SHAPES`, the original 4 geometric shapes) that restricts which shapes the generator draws, so existing callers' seeded output is unchanged; pass e.g. `shapes=(AnimalShape.DUCK, AnimalShape.GIRAFFE)` to draw animals instead, or `shapes=animal_shapes(4)` to take the first four animals in declaration order (`animal_shapes()` with no argument is the whole roster). A generated dataset's declared classes and stamped ids both narrow to `cfg.shapes` (see the `Fixed` entry on that below), so an animals-only run declares and numbers only its own animals; `class_names()` called with no `shapes` still spans the full vocabulary for the selected `class_mode`. Works with the existing detection/segmentation/OBB tasks and both writers with no writer code changes. See the "Animal shapes" section of `docs/datasets/shapes.md` and `examples/animate_synthetic_dataset.py --shapes animals`.
- `Task.KEYPOINTS` adds a fixed sixteen-keypoint anatomical pose schema — `mouth`, `eye`, `ear`, `head`, `neck`, `body_top`, `body_bottom`, `tail`, plus `front_elbow_left/right`, `front_limb_left/right`, `hind_knee_left/right` and `hind_limb_left/right` pairs — shared across quadrupeds, birds, and swimmers (a front limb is the paw, wing, or fin/flipper; every limb is articulated in two points because a limb's bend is the clearest pose cue; `left` = viewer-near by convention; placement rules documented in `fuse_augmentations/data/zoo/README.md`), with COCO keypoint annotations and a 15-edge category skeleton plus Ultralytics YOLO pose rows and `kpt_shape: [16, 3]`. `ear` and the four hind-leg points are the only optional landmarks (a fish's or a whale's silhouette shows pectoral fins/flippers but no hind legs, and neither taxon has an external ear); an animal without them carries NaN rows in its packaged table rather than faked points, and every writer already treats a NaN coordinate the same as a canvas-clipped one (`0.0 <= nan` is `False`), so it needs no special-casing. Every keypoint renders in a fixed per-name color, identical across all animals, and `examples/edit_zoo_keypoints.py` opens a minimal drag-and-save editor for fixing placements by hand. The per-animal outline, keypoints, skeleton edges, and CC0/Public Domain Mark provenance now live in one editable SVG per animal (`fuse_augmentations/data/zoo/<animal>.svg`, superseding the earlier per-animal JSON) — keypoints and their skeleton render visible by default, so opening the file shows shape and pose together; keypoint placement is hand-edited per the documented rule, not script-derived.
- `fuse_augmentations.data.symbols.SymbolShape` adds a third, analytically-computed shape family — 7 straight-edge 2D symbols (`kite`, `trapezoid`, `house`, `arrow`, `cross`, `teardrop`, `anchor`) needing no traced artwork, unlike `AnimalShape`. There is deliberately no plain-triangle member: it would collide in name with `GeomShape.TRIANGLE` for a shape this family does not need to keep. `Shape` widens to `GeomShape | AnimalShape | SymbolShape`, and `class_names()`/class ids append the 7 symbol classes after the existing 16 (23 total; `ClassMode.SHAPE_COLOR` 69 combined classes), so every prior class id is unchanged. Three of the seven (`arrow`, `cross`, `anchor`) are concave, so their segmentation polygon carries real shape information a box does not. `SyntheticConfig(shapes=symbol_shapes())` selects the family (`symbol_shapes(n)` mirrors `animal_shapes(n)`); works with the existing detection/segmentation/OBB tasks with no writer code changes. See the "Symbol shapes" section of `docs/datasets/shapes.md` and `examples/animate_synthetic_dataset.py --shapes symbols`.
- `Task.KEYPOINTS` now also works with `SymbolShape`, via a second, smaller 7-point structural schema — `center` (mandatory, each symbol's own area centroid/center of mass), `apex`, `tail`, `flank_left/right`, `base_left/right` (all optional) — distinct from the animals' 16-point anatomical one, with its own star skeleton (six edges from `center`) and, unlike the animals' identity mapping, a genuine `flip_idx` swap (`flank_left`↔`flank_right`, `base_left`↔`base_right`) since every symbol is drawn mirror-symmetric about its own vertical axis. A dataset carries exactly one keypoint-bearing family: pairing `Task.KEYPOINTS` with a geometric shape, or mixing `AnimalShape` and `SymbolShape` in the same `shapes` tuple, now raises `ValueError` at `SyntheticConfig` construction (previously only the geometric-shape case was checked). `fuse_augmentations.data.config.keypoint_schema_for(shapes)` returns the active family's schema (or `None`); `fuse_augmentations.data.landmarks.KeypointSchema` is the shared type both families' schemas (and the writers' `keypoint_schema` parameter) now use. See the "Symbol keypoint schema" section of `docs/datasets/tasks.md`.
- `SyntheticConfig.asymmetry_jitter` (default `0.0`, range `[0, 0.5)`) optionally narrows a randomly chosen half — left or right of a shape's own local vertical axis, before rotation — of each placed object by up to that fraction, breaking the identical left/right OBB margins that every mirror-symmetric shape in this package otherwise always shows. Applied via a new shared `fuse_augmentations.data.geometry._skewed`/`_placed(..., skew=)` step (skew, then rotate, then translate), so the polygon and, under `Task.KEYPOINTS`, its landmark table are always skewed together and never drift apart; `shape_polygon`, `animal_keypoints`, and `symbol_keypoints` all gain a matching `skew` parameter, defaulting to `0.0`. `circle` is always excluded (it never rotates either, so an unrotated skew would bias every instance toward the same absolute image direction). `0.0` (the default) draws no extra randomness, so every existing seeded configuration's output is unchanged. See "Breaking left/right symmetry" in `docs/datasets/customization.md`.
- `examples/render_shape_reference.py` renders one static, monochrome (black-on-white) reference image per shape into `docs/assets/shape-references/`, upright at each shape's own authored orientation — every symbol and animal is drawn mirror-symmetric about its own vertical axis, so this keeps a reference recognizable (an `arrow` pointing up, a `house` with its roof up) — with its plain axis-aligned detection box in blue and, for the two keypoint-bearing families (animals, symbols), keypoint dots and skeleton in the orange `animate_synthetic_dataset.py` uses for an occluded keypoint. The blue box is the detection box at this fixed reference pose — which, since the oriented box is derived in the shape's upright frame, is also exactly what the OBB task exports at an unrotated pose. Each shape is scaled independently to the largest size that fits its own outline inside the frame, rather than sharing one scale sized for the whole family, and carries no in-image filename caption — one shape per file already names it. See the "Shape reference" tabs in `docs/datasets/shapes.md`.
- `fuse_augmentations.data.letters.LetterShape` adds a fourth shape family — 26 capital letters (`a`-`z`), one filled outline polygon each like every prior family, but the only family authored **skeleton-first**: a letter is written as a set of keypoints plus the edges between them (`letters.json`'s `strokes` and `nodes` tables), and its drawable polygon is produced at import time by wrapping that skeleton in a constant-width pen stroke (`letters._stroke_outline`). Because the polygon is by definition the set of points within half a stroke width of the skeleton, every keypoint and every edge between two keypoints lies strictly inside the letter with half a stroke width of clearance — so joining a letter's keypoints in skeleton order sketches that letter through its own fill, and no landmark can ever land on the boundary or outside the ink. Every stroke tip caps as a semicircle and every convex corner rounds to an arc, leaving no sharp point anywhere on a letter; only the concave side of a turn stays angular, where the strokes' bodies already cover the corner. An edge may itself be a shallow circular arc (a signed sagitta on its `strokes` entry), which is what makes `o`/`c`/`g`/`s`'s bowls read as bowls rather than octagons, while the letters with no curve in a block face stay straight; how deep an arc may go is capped at load time, since the annotated skeleton joins keypoints with a straight line and a deeper arc would let its own chord escape the stroke. Seven letters (`a`, `b`, `d`, `o`, `p`, `q`, `r`) have an enclosed counter; since one polygon ring cannot hold a true hole, the graph edge closing each counter's loop is split into two flat-capped stubs a hairline apart before wrapping (`letters.json`'s `cuts` table), keeping the counter intact while the outline stays one simple, non-self-intersecting ring — that hairline is the single place in the family where a skeleton edge leaves the fill. A letter carries only the nodes its shape needs — wherever three consecutive keypoints sit on one straight run the middle one is not authored, so a plain stem is two keypoints rather than five. (`j` carries a top bar and `q` a steep tail from the era when the OBB was the minimum-area box and a diagonal-dominated hull leaned it off upright; the upright-frame OBB no longer depends on the hull, but the letterforms read better for it and stay.) The 15 slots carry default grid coordinates, but a letter may place any of its own nodes freely, which is what shapes `b`/`d`/`p`/`q`/`r`'s bowls, `o`'s oval, and `q`'s outward tail — and what keeps `d` and `o` from being the pixel-identical rounded rectangles they would otherwise both trace. `Shape` widens to `GeomShape | AnimalShape | SymbolShape | LetterShape`, and the full `class_names()` vocabulary appends the 26 letter classes after the existing 23 (49 total; `ClassMode.SHAPE_COLOR` 147 combined classes). `SyntheticConfig(shapes=letter_shapes())` selects the family (`letter_shapes(n)` mirrors `animal_shapes(n)`/`symbol_shapes(n)`); works with the existing detection/segmentation/OBB tasks and both writers with no writer code changes at all, since a letter needs no special-casing beyond being another outline in `geometry._base_polygon`'s lookup. See the "Letter shapes" section of `docs/datasets/shapes.md` and `examples/animate_synthetic_dataset.py --shapes letters`.
- `Task.KEYPOINTS` now also works with `LetterShape`, via a third, 15-point schema (`top_left` through `bottom_right`, row-major over the default node grid) whose keypoints *are* the stroke graph's own nodes and whose skeleton *is* the same graph's edges — unlike the animal and symbol schemas, a letter's skeleton genuinely differs per member (that is what makes it that letter), so `landmarks.KeypointSchema` gains an optional `skeleton_by_value` field (a per-shape-value edge override, `None` for every prior family, resolved by the new `KeypointSchema.skeleton_for(shape_value)`) that both the COCO writer's per-category `skeleton` and the animated-preview overlay read from one shared source. Unlike the animal and symbol landmarks, which need an inward inset to keep them off their own outline's boundary, a letter's keypoints need no correction at all: the wrap that produces the outline leaves every node half a stroke width inside the fill, including a stroke's free end, which sits at the center of its own round cap. Nine letters (`b`, `d`, `h`, `i`, `n`, `o`, `s`, `x`, `z`) place one node off its default grid slot, the same technique `SymbolShape.KITE`'s unequal diagonal lengths use, because their regular block form is otherwise exactly invariant under a 180-degree rotation about its own center — the same keypoint-identity ambiguity that already excludes `GeomShape.SQUARE`/`CIRCLE` and a plain triangle from a keypoint table. `flip_idx` swaps each row's left/right slot and holds the middle column fixed; note that a mirrored letter is generally a different letter, so a horizontal flip is not label-preserving here the way it is for an animal silhouette, and the field is published for format completeness. A dataset still carries exactly one keypoint-bearing family; mixing any two of `AnimalShape`/`SymbolShape`/`LetterShape`, or pairing a geometric shape with any of them, raises `ValueError` at `SyntheticConfig` construction. See the "Letter keypoint schema" section of `docs/datasets/tasks.md`.
- `fuse_augmentations.data.symbols`'s and the new `fuse_augmentations.data.letters`'s raw shape data (outline/landmark literals, stroke graphs, counter-opening cuts, free node positions) now live in packaged JSON assets (`symbols.json`, `letters.json`) loaded at import time, the same externalized-data pattern `AnimalShape`'s SVG `zoo/` assets already use — the modules themselves are pure loaders. No public API changed. (Superseded later this cycle: see "Symbols and letters ship as editable SVGs" below, which replaces these two JSON files with per-shape SVGs.)

### Fixed

- `Annotation` now carries the `KeypointSchema` its landmark table was built against instead of inferring the family from the table's *length*. The lengths (16 animal, 7 symbol, 15 letter) happened to be distinct, but the inference had already forced a workaround in the test suite when letters were added, and it left an annotation unable to state its own family — so a writer had to be told separately and the two could disagree.
- `DatasetWriter`/`get_writer` no longer default `keypoint_schema` to the *animal* schema. A directly-constructed symbol or letter pose writer that omitted it silently emitted a 16-landmark animal header over 7- or 15-landmark rows; `Task.KEYPOINTS` without a schema now raises.
- `class_names()`/`class_id()` require an explicit `shapes` vocabulary. The default spanned all 49 shapes while `SyntheticConfig` defaults to the 4 primitives, so the obvious call for a default config returned a vocabulary twelve times too large — silently, since the ids still resolved.
- **A generated dataset's annotation class ids now resolve against the class vocabulary written beside them.** A run narrowed to a shape family that is not a prefix of the full `Shape` vocabulary — any animal, symbol, or letter run — wrote a *renumbered* COCO `categories` block (and YOLO `nc`/`names`) but *globally-numbered* ids on its annotations: a `shapes=(SymbolShape.KITE,)` dataset declared `[(1, 'kite')]` and then annotated every object with `category_id: 17`. Any COCO reader building the usual `category_id -> label` map raised `KeyError` on the first annotation, and any YOLO loader read a class index past the end of its own `names`. The two sides had each narrowed independently: the writer's category list took `class_names(..., shapes=config.shapes)` while `class_id_of` indexed the unnarrowed 49-shape list. Narrowing is now end-to-end — `class_id_of` gains the same optional `shapes` argument `class_names` has, and `SyntheticGenerator` passes its config's `shapes` to both — so a run's ids are local to its own vocabulary and every written document is internally consistent. The default geometric vocabulary is unaffected (its four shapes lead the full enum, so its narrowed and global ids coincide — which is exactly why no existing fixture caught this); any *other* family's ids shift down to start at `0`, so compare datasets by class name rather than by raw id. Reported downstream by lit-YOLOs; regression-tested end-to-end for both formats on three non-prefix families.
- **A bare-string `class_mode` no longer selects the wrong class naming.** `ClassMode` is a str-Enum, so the documented `SyntheticIterableDataset(class_mode="shape")` spelling — forwarded verbatim into `SyntheticConfig` — compared *and hashed* equal to `ClassMode.SHAPE` while failing every `is` identity test `class_names`/`class_id_of` branch on. `class_names("shape")` therefore returned the `shape_color` product, and `class_id_of`'s per-mode cache (keyed on that equal hash) served whichever spelling populated it first to the other, so the mismatch surfaced as an order-dependent `KeyError` rather than a clear error. `SyntheticConfig` now coerces `class_mode` to a real member in `__post_init__`, and both vocabulary functions coerce their own argument, so every spelling behaves identically and an invalid one raises `ValueError` at the boundary.
- `polygon_to_obb`'s chosen box orientation no longer flips between renders of the identical shape at different rotation angles. Originally a symptom of the minimum-area algorithm picking among equal-area candidate rectangles by iteration order; first patched with a rotation-invariant tie-break, then resolved outright by the upright-frame OBB semantics below, which have no candidates to tie.

### Changed

- **`fuse_augmentations.data` API restructure.** The submodule grew four shape families in four successive commits, and the seams between them had started to cost more than the features. Five structural changes. **These are breaking:** no compatibility shims are kept, and the deprecated `data.shapes` module is removed along with them.

    - **One shape-family registry.** `fuse_augmentations.data.families` is now the only place that knows which families exist: each contributes one `ShapeFamily` entry to `SHAPE_FAMILIES`, and every other module reads that instead of naming the families itself. Adding a family previously meant editing six sites that each encoded the family list differently (a type union, a dict keyed by class, a dict keyed by landmark-table *length*, an outline if-chain, an `isinstance` chain, and five re-exports per family) — and missing one failed quietly: forget the landmark dispatch and the family generated no keypoints at all, which the writer then serialized as a structurally valid all-zero table. New exports: `SHAPE_FAMILIES`, `ShapeFamily`, `ALL_SHAPES`, `family_of`, `shape_outline`.
    - **One owner for `task`.** `generate_dataset` no longer takes `task=` or `class_mode=` arguments; both are `SyntheticConfig` fields, reachable as keywords. The task previously had two readers — the generator read the config's, the writer read the argument — which needed a `None` sentinel, a cross-check, and a documented conflict error. Passing a `config` *and* config-field keywords is now an error rather than silently ignoring one. `SyntheticConfig(task="keypoints")` coerces its string form, as `class_mode` already did.
    - **Structured class identity.** `class_vocabulary()` returns `ClassEntry` records carrying the shape and color each class came from, so the writers no longer recover structure from a class *name* by splitting on `"_"` — correct only while no shape or color value contained an underscore.
    - **No torch on import.** `fuse_augmentations.data` resolves `SyntheticIterableDataset` lazily (PEP 562) — the one remaining use of a module-level `__getattr__` here. Note the parent `fuse_augmentations` package still imports torch eagerly, so end-user import time is unchanged until that is addressed separately.
    - **Open extension points.** `register_writer()` adds an output format without forking (`get_writer`/`generate_dataset` accept any registered key); `SplitRatios.custom()` takes arbitrary split names instead of only train/val/test.
    - **One base class instead of a hand-written union.** Every family enum now derives from `data.shape_enum.ShapeEnum`, and `Shape` *is* that base rather than `PrimitiveShape | AnimalShape | SymbolShape | LetterShape`. A type checker reads the membership off each family's own declaration, so adding a family is a single edit to `SHAPE_FAMILIES` instead of two sites that could drift. `isinstance(value, Shape)` behaves as before: it accepts any family's member and still rejects a bare `"duck"` string. The one trade is that an unregistered `ShapeEnum` subclass now type-checks and fails at the registry lookup instead of at config validation.
    - **One fill type.** `Fill` — a frozen dataclass carrying the `(r, g, b)` to draw with plus the `Color` name it came from, when it had one — is what a fill is everywhere past the config boundary. `colors` was a `tuple[Color, ...]`, so a custom fill had no path at all while `background` already took any RGB; it now accepts a `Color`, a raw `(r, g, b)` triple, or a `Fill`, and `SyntheticConfig` normalizes every spelling through `Fill.parse()` at construction, the way `task` and `class_mode` already coerce. A raw fill has no name, so `Fill.label` falls back to its hex value, which keeps `ClassMode.COLOR` and `ClassMode.SHAPE_COLOR` well defined without inventing color names. **Breaking:** `config.colors` reads back as `Fill` objects rather than the members or tuples passed in. `Color` remains the named vocabulary and now carries its RGB payload on the member itself (via `__new__`) instead of a three-entry dict rebuilt on every `.rgb` access; members are unchanged as strings.

- **Renames** (breaking — the old names are gone): `GeomShape` → `PrimitiveShape` (moved to `data.primitives`), `shape_polygon` → `shape_outline` (moved to `data.families`), `class_id_of` → `class_id`, `data.landmarks` → `data.keypoints`, `Task.OBB`'s canonical value `"oriented_bounding_boxes"` → `"obb"` (the long spellings no longer parse). The deprecated `data.shapes` shim module is removed. `data.geometry` keeps only family-agnostic math. The per-family `animal_shapes(n)` / `symbol_shapes(n)` / `letter_shapes(n)` helpers are removed — `tuple(AnimalShape)[:n]` says the same thing. Family names (`AnimalShape`, `ANIMAL_KEYPOINT_NAMES`, …) are no longer re-exported from `fuse_augmentations.data`; import them from their family module.

- **Oriented boxes are upright-frame, not minimum-area.** `Annotation.obb_corners` (and both writers' OBB output) is now the shape's axis-aligned box in its own pre-rotation frame, rotated rigidly by the placement angle — its sides run along and across the shape's upright (symmetry) axis, the way a human annotator would draw it. Previously it was the true minimum-area rectangle (rotating calipers), which must sit flush to a convex-hull edge: for a shape with no horizontal or vertical hull edge in its upright pose (`kite`, `arrow`, `teardrop`, several animal silhouettes) that box leaned visibly off the shape's own axis — geometrically tighter, but wrong as a pose annotation. `Annotation` gains an `angle` field (radians, default `0.0`) recording the placement rotation — inserted *before* `keypoints`/`keypoint_schema`, so a positional caller passing keypoints as the fifth argument must switch to keywords — and `geometry.polygon_to_obb(points, angle=0.0)` takes the angle explicitly — with the default it returns the plain axis-aligned box. The rotating-calipers machinery (convex hull, candidate scan, tie-breaking) is deleted. **Breaking** for any consumer that expected minimum-area boxes; exported box *area* for a given shape is now angle-invariant.

- **Symbol SVGs now carry a `skeleton` group.** The seven `data/symbols/<symbol>.svg` assets gain the same `<g id="skeleton">` visualization lines the animal assets always had (the letters' `strokes` graph plays that role for them), so every packaged asset shows shape, keypoint dots, and edges together in any SVG viewer. Like the animals', the group is a pure viewing aid regenerated by `examples/edit_shape_keypoints.py` on save — nothing in generation or validation reads it — and a unit test now pins that each symbol's lines match its own keypoints.

- **Synthetic-dataset docs split into their own section.** The single 800-line `docs/guides/synthetic-datasets.md` is now a top-level "Synthetic datasets" section (`docs/datasets/`) with five pages: overview (install + quickstart), shape families, tasks and keypoints, output formats, and customization/extension. Content is unchanged apart from cross-page links; inbound links from the README and packaged-asset READMEs follow. The docs site's top navigation gains the multipage menus this section needs.

- **Symbols and letters ship as editable SVGs.** `symbols.json` and `letters.json` (introduced above) are replaced by `data/symbols/<symbol>.svg` and `data/letters/<letter>.svg`. Symbols use the animals' outline schema; letters use a *stroke-graph* schema (named nodes plus `<line>` edges carrying `zoo:bulge` and `zoo:cut`, no outline — the silhouette is still generated by stroking the graph, so stroke width and counter gap stay tunable). All three families are read by one parser, `data.svgio`, and edited by one tool: `examples/edit_zoo_keypoints.py` is now `examples/edit_shape_keypoints.py` and opens any of the 45 keypoint-bearing shapes. Generated geometry is unchanged, pinned by a checked-in snapshot of all 49 shapes' outlines and landmark tables (`tests/test_unit/test_data/_golden_geometry.npz`).

- **`examples/animate_synthetic_dataset.py`'s family previews now show every member of the family they preview.** The generator picks each object's shape uniformly, so a clip of a few images with a handful of objects each showed a lucky subset — a letters preview typically reached 16 or 17 of the 26 letters, since covering all of them needs roughly 145 drawn objects. Each vocabulary now sets its own scene density and clip length (`SCENES`, the new `CLIP_IMAGES`), trading object size for object count as the vocabulary grows, and the script then walks its seed forward until the stream it renders actually contains every shape, printing the seed it settled on and raising rather than writing a preview with shapes missing. `--num_images` now defaults to the vocabulary's own clip length instead of a flat `6`; `--shapes geometric` keeps its original scene and seed.

- **`fuse_augmentations.data.shapes` moved to `fuse_augmentations.data.geometry`** — the old path keeps working as a deprecated re-export shim that emits a `DeprecationWarning` on import, so existing `from fuse_augmentations.data.shapes import ...` code is unaffected for now; update the import to `fuse_augmentations.data.geometry`, as the shim will be removed in a future release (removed above, later this cycle). It forwards the geometry surface the module published (`CIRCLE_POINTS`, `RECT_ASPECT`, `GEOMETRIC_SHAPES`, `rotate_polygon`, `shape_polygon`, `polygon_to_bbox_xyxy`, `polygon_to_obb`, `bbox_iou`).

- **`Shape` is now `GeomShape | AnimalShape`, not a single `Enum`** — the drawable vocabulary is split by family, `GeomShape` (square, rectangle, triangle, circle) in `fuse_augmentations.data.geometry` and `AnimalShape` (the 12 animal silhouettes) in `fuse_augmentations.data.animals`. `isinstance(value, Shape)` still works and still rejects a bare string, but `Shape.SQUARE`, `Shape("square")`, `tuple(Shape)`, and `for s in Shape` no longer work — a plain union has no members and is not iterable. Use `GeomShape` directly for the old enum-only behavior, or build the full vocabulary as `[*GeomShape, *AnimalShape]`. (Widened again above, later this cycle, to `GeomShape | AnimalShape | SymbolShape | LetterShape`, then replaced outright by the one-base-class registry.)

- **Animal and symbol outline normalization now centers on the polygon's area centroid (center of mass), not the arithmetic vertex mean** — `fuse_augmentations.data.landmarks._frame` (shared by `AnimalShape` and `SymbolShape` loading) previously subtracted `points.mean(axis=0)`, which drifts off a shape's true visual middle whenever vertices are spread unevenly along its edges (an arrow's barbs, a giraffe's long neck); it now subtracts the polygon's shoelace-formula area centroid instead. `GeomShape`'s own analytically-constructed shapes (square, rectangle, triangle, circle) are unaffected, since their vertex mean already equals their area centroid by construction. This shifts every animal's and symbol's rendered position by the (typically small) offset between its old vertex-mean center and its true center of mass; no public API changed.

## [0.10.0.dev0] - 2026-08-01

### Added

- `fuse_augmentations.data`: standalone synthetic dataset generator that draws colored shapes (square, rectangle, triangle, circle) on a canvas and exports **COCO** or **YOLO** datasets for **detection**, **segmentation**, and **oriented-bounding-box (OBB)** tasks. One `generate_dataset(output_dir, num_images, fmt=, task=, class_mode=, split_ratios=, seed=)` facade (also re-exported as `fuse_augmentations.generate_dataset`) over a format-agnostic `SyntheticGenerator` and `CocoWriter`/`YoloWriter`; `class_mode` selects shape / color / shape_color classes; rectangle plus per-shape rotation give OBB real orientation, and generation is fully seeded for byte-identical output. Generation and writing are streaming (one sample materialized at a time): `SyntheticGenerator.generate(n, seed=)` yields a lazy `Sample` iterator, the writers persist single-pass, and `generate_dataset` streams to disk so arbitrarily large datasets stay memory-bounded. `fuse_augmentations.data.datasets.SyntheticIterableDataset` (a worker-shard-aware `torch.utils.data.IterableDataset`) feeds samples straight into a `DataLoader` with no disk round-trip. Rendering uses Pillow, now a base dependency. See `docs/datasets/` and `examples/generate_synthetic_dataset.py`.
- `inverse()` test-time de-augmentation: pass the image and matrix from a `return_matrix=True` forward call to map predictions (image, masks, xyxy/xywh boxes, keypoints) back to the original frame through the inverse of the fused pixel matrix in one `grid_sample`. Supported only for a pipeline that fuses to a single affine or projective segment; raises a named error for crop-resize, color/lookup/blur, exact-only or passthrough segments, multi-segment pipelines, and a missing paired matrix. Keypoints and masks recover to sampling precision; bounding boxes are axis-aligned (AABB) and recover exactly only under axis-aligned transforms (flip, scale, translation), inflating under rotation, shear, or a projective warp — a rotated box is stored as axis-aligned corners, so round-tripping through `inverse()` encloses a larger box than the original (a 23-degree rotation inflates a 20x20 box by ~7 px per edge). The paired matrix is not validated against the image — passing a matrix from a different call yields silently wrong geometry.
- `pipeline_dtype="bfloat16"|"float16"` opt-in on `Compose`: runs the image warp and fused color/lookup applies in half precision on a non-CPU device for roughly 2x memory bandwidth. Matrix composition and inversion stay float32/float64 and are cast to the low precision only at the sampling-grid boundary, so the public `transform_matrix` always keeps full precision. Default (`None`) is bit-identical to before; CPU ignores the option.
- Gaussian blur folds and commutes instead of being a hard fusion barrier. A `SPATIAL_LINEAR` op category plus two composition laws let it fuse in the cases that are provably safe: consecutive blurs fold into one operation by adding their per-axis variances (batched Kornia `gaussian_blur2d`, per-sample sigmas preserved), and a blur that precedes a fusible affine commutes to the chain end so the two share one warp — first only through an axis-aligned affine (diagonal covariance, `sigma_i' = |a_ii| * sigma_i`), then extended to a rotated or sheared one via the full `A*diag(sigma^2)*A^T` covariance, applied as a per-sample sampled Gaussian kernel through `conv2d` (kernel radius from the 3-sigma rule, clamped). Any downscaling affine (rotated or not) keeps the blur a barrier, since a blur commuted after a downscale can no longer prefilter the aliasing the downscale introduces; so do rotated/sheared runs on the Albumentations native cv2 path (native matrix composition there would perturb its own sampling stream, so it folds consecutive blurs but does not commute them through an affine), Kornia's `RandomSharpness` (not linear shift-invariant, so blur and sharpen do not compose into one `conv2d`), and non-linear kernels generally. `fusion_plan` renders the fused op as `gaussian_blur(...)` and counts it in `n_warps_saved`.
- Per-channel non-linear scalar maps (`gamma`, `solarize`, `posterize`) fuse into a single lookup table instead of each costing a full-tensor pass, via a new `POINTWISE_LUT` category and `FusedLUTSegment`. The Albumentations uint8 path composes each op's own native byte map over the `0..255` ramp by integer indexing, bit-exact against the native sequential chain; the float-tensor path samples the composed map on a 1024-entry `[0, 1]` grid with linear interpolation, sharpened at discontinuities (a solarize threshold, a posterize step) with a detected-jump sharp-step rule instead of smearing them across a grid cell — still a documented interpolation-tolerance path, not exact. `equalize` — previously a hard barrier because its lookup table is a per-image per-channel histogram that cannot be pre-composed at plan time — is registered as a lookup op whose table is built at runtime from the image histogram in each backend's own convention, so a `[gamma, equalize, posterize]` run fuses into one pass instead of splitting into three. Cross-channel ops (saturation, hue) and Albumentations masked/luminance equalize stay barriers, since they are not per-channel scalar maps.
- `padding_mode="per_transform"` (also accepted by `from_config`/`from_params`) opts a fused geometric run into honoring each transform's own border mode instead of one Compose-level override applied to all of them — Kornia reads it from each `RandomAffine`'s own flags, Albumentations from `border_mode` plus `fill`, TorchVision from `fill`. A mode without an exact `grid_sample` equivalent (Albumentations reflect/wrap/nonzero fill, TorchVision nonzero fill) is kept as a native passthrough boundary with a `UserWarning` rather than silently coerced; the split cause shows up as `split_reason` (`"border_mode_change"` or `"opaque_border_mode"`) on the segment descriptors. Without the opt-in, the existing single-override path is unchanged, covered by a bit-identical regression test.

### Fixed

- `inverse()` normalizes and inverts the paired matrix in full precision even when the augmented image is low precision, casting only the sampling grid to the image dtype at the `grid_sample` boundary (float32/float64 images unaffected). The Albumentations-backed affine/projective segments' public matrix now keeps the image's own precision (float32 or float64) instead of always promoting to float32; only a float16/bfloat16 image promotes it to float32, so float64 Albumentations pipelines no longer lose matrix precision.
- The `RandomRotate90`/D4 quarter-turn matrix path fused with an interpolating op rotated backwards: `RandomRotate90`'s `k90` and the D4 `r90`/`r270` angles are now negated in `build_matrix`/`_d4_matrix` so the fused matrix agrees with native `np.rot90(+k)` and `exact_apply`.
- The downscale antialias prefilter mapped its blur sigma to a magnitude-sorted singular value instead of the image axis it actually shrinks, so an anisotropic downscale could blur the wrong axis; it now reads the diagonal directly for axis-aligned warps and falls back to isotropic worst-axis blur only when the linear part is rotated or sheared. A fused Albumentations `Perspective` with `keep_size=False` (which returns a differently shaped crop) now raises `NotImplementedError` instead of the batched shape-preserving engine silently mis-reproducing it in one warp.
- Compose with auxiliary `data_keys` now routes Albumentations `RandomResizedCrop` through a real `CropResizeSegment` instead of an image-only passthrough, so masks/boxes/keypoints follow the crop's output size; image-only pipelines keep the original passthrough.
- `DatasetWriter.write` documents that splits must be consumed once each, in order: the mapping `generate_dataset` passes holds lazy views over one shared sample stream, so iterating out of order or twice silently redistributes or empties splits.
- Backend transform replay parity: corrected Kornia affine composition and quarter-turn direction, Albumentations keep-size perspective scaling, and TorchVision rotation-convention handling, with deterministic native-replay coverage added for affine terms, perspective, crops, D4 operations, probability masks, non-square inputs, and clipping behavior.
- The blur-commute singular-value guard required the smallest singular value to be exactly `1.0`; a pure rotation's true smallest singular value is `1.0` but rounds just below it in float32 (e.g. `0.99999994` at 47.3°), so it sporadically missed the commuted-covariance fusion and fell back to the slower (but still correct) separate-warp path. A `1e-6` tolerance now admits it. Under `clip_policy="per_op_parity"`, a contrast op following a clamped intermediate previously took its mean-luminance midpoint from the pre-clamp values, drifting from native by ~5.7e-2; it now recomputes the mean from the clamped intermediate (max divergence vs. a native per-op-clamped chain measured at ~6e-8). `clip_policy="final"` (default) is unaffected in both cases.

### Changed

- `compile=True` on `Compose` now also wraps the fused color-matrix application and the lookup-table application in their own dynamic-shape `torch.compile` regions (previously only the warp core), cutting kernel launches for color- and lookup-heavy pipelines on GPU; each tensor core compiles separately so varying height, width, and batch do not trigger a recompile storm. Per-sample probability masks and the equalize runtime histogram table stay outside compiled regions. Default `compile=False` path and outputs are unchanged.
- Base dependencies were audited: `pillow`, `rich`, and `scipy` were dropped as unused by shipped code (`scipy` moved to the dev group for its one precision test), and `pillow` was reinstated shortly after as a real base dependency for the synthetic-data generator's rendering (see Added, above). CI now also exercises the 3.11, 3.13, and 3.14 legs the package classifiers advertise, backfilling a missing 3.12 package-install leg; the contributing guide now notes that no CI runner has GPU access, so CUDA correctness has no automated coverage.
- Pipeline pickling (what a `DataLoader` worker receives) rebuilds every derived dispatch attribute from a shared builder on unpickling instead of only at construction, so a pickle produced before an attribute existed is reconstructed rather than raising `AttributeError` on first forward; the output-backend flag is stored so its converter is re-derivable while legacy pickles keep their restored one. `fusion_plan` now reports a backend-boundary `split_reason` on the second of two adjacent fused segments whose resolved backends differ (previously only crop and passthrough boundaries carried one), and marks Albumentations cv2-execution fused/projective segments as CPU-passthrough on non-CPU pipelines, since each such warp hides a host round-trip.

### Performance

- The oriented bounding box is derived from the polygon on first access rather than computed for every annotation at generation time. It was a convex hull plus a rotating-calipers scan per object, paid by detection, segmentation and keypoint runs that never read the result — **75% of generation time** on a mixed-family run, measured. A detection run over 538 objects went from 311 ms to 56 ms. `Annotation.obb_corners` reads the same as before; it is no longer a constructor argument. (This machinery is deleted outright in the next cycle's upright-frame OBB rewrite.)
- Per-warp host syncs and redundant FLOPs cut on several hot paths: the exact-D4 classification (and its device-to-host readback) is skipped on non-CPU tensors, where the lossless flip/rot90 shortcut is a near-bit-identical micro-optimization not worth draining the accelerator stream every warp; the fused color matrix applies via a single `baddbmm` over the 3x3 linear part plus bias column instead of a full homogeneous matmul over an augmented block, dropping roughly a quarter of the FLOPs; `normalize_matrix_io` expands to a closed-form analytic product, removing two intermediate matrix allocations and two `bmm` calls per crop-resize warp; a batch-size sentinel tensor lets `build_matrix` read `.shape[0]` instead of `.item()` inside fused GPU chains, removing another device-to-host sync; and both Albumentations cv2 warp paths drop a redundant `.copy()` after `ascontiguousarray()` since `torch.stack` already breaks aliasing. Each rewrite is pinned by a parity test against its original form.

- `execution="cv2" | "torch"` flag on `Compose` for fused Albumentations segments: `"cv2"` (default) keeps per-sample cv2 warps bit-identical to earlier releases; `"torch"` opts into one batched `grid_sample` per segment (batch-size-independent throughput, native GPU/MPS execution).

- `output_backend="numpy"` now converts each convertible target of a multi-target output (image, mask); coordinate targets remain tensors.
- `Normalize` (Kornia, TorchVision v2, standard Albumentations) now fuses into the color matrix as a per-channel affine, deleting one full-tensor pass from pipelines that end in normalization; the final gamut clamp is suppressed for the normalized output (image-statistics Normalize modes remain passthrough).
- `clip_policy="final" | "per_op_parity"` on `Compose`: `"final"` (default, unchanged) clamps once after the fused color matmul; `"per_op_parity"` splits the fused color run wherever an intermediate would leave `[0, 1]`, matching a native per-op clamped chain.
- Opt-in `compile=True` on `Compose`: wraps the warp core (matrix normalize → `affine_grid` → `grid_sample`) in `torch.compile` on torch ≥ 2.2 (no-op otherwise and on CPU; default off, outputs unchanged).
- Opt-in `antialias=True` on `Compose`: crop-resize segments prefilter aggressive downscales (worst-axis scale < 0.5) before the single warp, removing aliasing; default off, outputs bit-identical.
- Opt-in `substitute_passthrough=True` on `Compose`: replaces registered non-fusible ops with an installed backend's torch-native equivalent (initially Albumentations `GaussianBlur` → Kornia `RandomGaussianBlur`) so GPU pipelines stay on-device; behaviour-changing and warns per substitution.
- Passthrough segments now cross the CPU boundary once per batch (one device-to-host and one host-to-device transfer per segment instead of per sample), with identical numerics.
- `fusion_plan` marks passthrough entries with `[CPU passthrough]` on non-CPU pipelines, and `fusion_plan_descriptors` carries machine-readable `split_reason` / `barrier` / `refused` fields.
- Opt-in `mask_interpolation="bilinear"` on `Compose` and `from_params`: differentiable soft-mask sampling for auxiliary masks (float masks required; labels mix at boundaries). Default `"nearest"` is unchanged and bit-identical.
- Memory benchmark (`experiments/bench_memory.py`): peak memory + allocation counts, fused vs native, per pipeline and batch size.
- `backend="native"` is now a first-class option for `from_config` (and `from_params` gains a `native` flag): the zero-dependency, fully batched pure-torch engine, including native `brightness`/`contrast` builders. Opt-in — backend auto-detection remains the default.
- `return_matrix=True` per-call flag: returns `(output, matrix)` without reading shared instance state, making matrix retrieval thread-safe; the `transform_matrix` property remains for compatibility.
- One `finfo(dtype).eps`-scaled near-singular threshold shared by all three matrix-inversion paths (torch, compile-friendly, numpy); `fusion_plan` / `fusion_plan_descriptors` results are cached (device-aware, pickle-safe).

### Fixed

- Corrupt rotation matrix in the TorchVision batch-size-1 CPU cv2 fast path (`sin` computed as `cos`).
- `from_params(scale=...)` now draws a single isotropic factor shared by both axes, as documented; explicit `scale_x`/`scale_y` keep independent draws.
- cv2 `"reflection"` padding now maps to `BORDER_REFLECT_101`, matching torch `grid_sample(padding_mode="reflection", align_corners=True)`.
- Bounding-box zero-`w` guard uses `finfo.eps` (the previous `finfo.tiny` clamp overflowed float32 to `inf`).
- Near-singular affine matrices raise consistently across the torch and cv2 inversion paths; eager and `torch.compile` branches of `inv3x3` share one threshold.
- cv2 fast-path activation gates respond to `torch.manual_seed`; Albumentations segment `forward` no longer consumes RNG draws for inactive transforms.
- `uint16` NumPy inputs are normalised to `[0, 1]` (previously cast without rescaling).
- Albumentations native dict path raises instead of silently dropping non-image keys; unrecognised transforms are rejected in Albumentations-backed pipelines.
- `transform_matrix` resets to `None` at every forward, so exact/passthrough-only calls no longer report a stale matrix.
- `fuse_aug.__version__` is exported, matching `fuse_augmentations.__version__`.

### Changed

- **Fused contrast midpoint is now the per-image mean luminance** (matching native TorchVision/Kornia `ColorJitter` semantics) instead of a fixed `0.5`. Fused pipelines containing contrast produce different (more native-faithful) values than previous releases; pin the previous behavior only by comparing against your own stored baselines. Parity holds under `reorder=NONE`; with pointwise reordering the mean is taken over the warped image and diverges from native by construction.
- Coordinate-changing passthrough ops (elastic/grid/optical distortion and similar) now **raise `ValueError`** when they execute in a multi-target pipeline (previously a `UserWarning`): auxiliary targets skip passthrough segments, so continuing would silently misalign masks/boxes/keypoints. Kernel/pointwise passthrough (blur, noise) with auxiliary targets no longer warns — skipping them is the correct semantics.
- `same_on_batch=True` on Albumentations-backed fused segments now shares the sampled parameters across the batch, not just the activation decision.
- Documented color-fusion accuracy caveats (final-only clamping; fixed 0.5 contrast midpoint) and the seeding contract limits between warp backends.
