## Project-specific facts

- Python support starts at 3.10. Use `uv` and treat `pyproject.toml` and `.github/workflows/` as the source of truth.
- The package uses a `src/` layout and supports optional Kornia, TorchVision, and Albumentations backends.
- Documentation Python examples in `README.md` and `docs/**/*.md` are generated into ignored `tests/integration/` modules with `.github/scripts/generate_doc_tests.py`. Write them as plain ```` ```python ```` script blocks (`print(...)` + a following output fence in `<details>`) — never as ```` ```pycon ```` `>>>` sessions, which are reserved for `src/**` docstrings.
- Run `python .github/scripts/generate_doc_tests.py` before `python -m pytest tests/integration -q` when changing executable documentation.
- CI regenerates the documentation suite in the all-extras job. Do not commit generated files; there is intentionally no Makefile wrapper.
- When you edit any shape definition under `src/fuse_augmentations/data/` (`geometry.py`, `animals.py`, `symbols.py`, `letters.py`, `landmarks.py`) — a new/changed outline, keypoint table, or the OBB/centroid logic they share — validate the change (`uv run pytest tests/test_unit/test_data -q` and `uv run pytest --doctest-modules src/fuse_augmentations/data -q`), then regenerate whichever previews the change actually affects: `python examples/render_shape_reference.py` (static field-guide PNGs under `docs/assets/shape-references/`, one `<prefix><shape>.png` per shape) and `python examples/animate_synthetic_dataset.py --shapes <family> --task all` (animated clips under `docs/assets/datasets/`) for the affected family. Look at the regenerated images before calling the change done — a mis-placed keypoint or a wrong outline is visible there, not just in a passing test. Run the animation command bare, without piping it through `head` — a closed pipe kills the loop partway and leaves the later tasks' clips stale at their previous settings, which looks exactly like a successful run. Each vocabulary carries its own object count (`SCENES`) and clip length (`CLIP_IMAGES`) sized so the whole family fits in one clip, and `_covering_stream` then walks the seed until the rendered stream actually contains every member; it prints the seed it used, and raises rather than shipping a preview with shapes missing.
- `examples/render_shape_reference.py`'s blue box is each shape's plain axis-aligned **detection** box at its fixed, upright reference orientation — not `polygon_to_obb`'s minimum-area **OBB**. The two differ for any shape whose true minimum-area OBB is not axis-aligned at that pose (e.g. the `arrow`, whose OBB is a diamond flush to its barb tips) or whose OBB candidates tie (any acute or right triangle, for instance — see `GeomShape.TRIANGLE`'s docstring). The real, rotated OBB is what the generator's actually-rotated samples carry — see the `--task obb` animated previews and `docs/guides/synthetic-datasets.md`'s "Tasks" section for that. Do not "fix" the reference script to draw the rotated OBB instead; that was tried and reverted because it produces a tilted or arbitrarily-tied box for a shape shown in a fixed pose, which is confusing rather than informative for a field-guide reference. `SymbolShape` has no plain-triangle member for the same tie reason — don't add one back without solving it.
- A `LetterShape` member is authored **skeleton-first** — keypoints plus the edges between them, in `letters.json`'s `strokes` (which node pairs are joined) and `nodes` (where a node sits, overriding its default grid slot outright) tables — and `letters._stroke_outline` wraps that skeleton in a constant-width pen stroke to produce the drawn polygon. Never hand-author a letter outline, and never post-correct a letter keypoint: because the polygon *is* the set of points within half a stroke width of the skeleton, every keypoint and every skeleton edge is strictly inside the fill by construction, and any "fix" that moves a keypoint off its node breaks exactly that guarantee (an oversized inward inset once did, pushing keypoints most of the way to the next node so `o`'s and `b`'s skeletons chorded across their counters). `test_skeleton_edges_lie_inside_the_outline` in `test_letters.py` is the guard.
- A stroke edge may be a shallow circular arc: a third element on its `letters.json` `strokes` entry is its signed sagitta as a fraction of its own chord, positive to the left of the authored `u -> v` direction. Two bounds are enforced at load time and must not be worked around — an edge's arc may not rise past `letters._MAX_SAGITTA` (the annotated skeleton joins keypoints with a *straight* line, so a deeper arc lets its own chord escape the stroke — note the bound is on the arc's absolute height in multiples of half the stroke width, not on the authored chord fraction, since that height is exactly how far the chord strays whatever the chord's length), and an edge named in `cuts` must stay straight (splitting a sampled arc into two hairline-separated flat caps tilts the two caps relative to each other and crosses the ring). Bow a neighbouring edge instead, or move the cut. Keep curves to letters that genuinely have them: `a e f h i k l m n t v w x y z` are straight-stroke letterforms and should stay that way.
- Author a letter with **only the nodes its shape needs**: if three consecutive keypoints sit on one straight run, the middle one carries no information a viewer could not read off its neighbours, so it must not be authored — a plain stem is two keypoints, not five. Corners, junctions, ends, and points along a curve are what remain. A cut edge's endpoints are exempt (the slit is anchored there), as is any node between two bowed edges.
- A `cuts` entry may name **where** along its edge the slit sits — a third element, the fraction from the endpoint it lists first (default the midpoint). A bowl hung off a stem breaks as near that stem as fits, so it reads as a curve just touching a vertical line; a free-standing ring breaks along its bottom. "As near as fits" has a hard floor: a stub shorter than `letters._MIN_STUB` half-widths is swallowed whole by the stroke it branches off and the ring self-intersects, so `_reject_tight_cuts` refuses it at load time and names the range that edge can carry. Do not work around it by shrinking the stroke width — move the cut inward or put it on a longer edge.
- The 15 keypoint slots are a fixed dataset-wide count (both output formats require it), but their grid coordinates are only defaults — place nodes freely through `letters.json`'s `nodes` table when the letterform needs it. Two rules that table exists to satisfy: (a) no letter may be invariant under a 180-degree rotation about its own center, or its keypoint identities are ambiguous under the generator's continuous random rotation — the same reason `GeomShape.SQUARE`/`CIRCLE` and `SymbolShape`'s missing plain triangle carry no keypoint table (`test_no_letter_is_invariant_under_180_degree_reflection`; `h i n o s x z` are the seven whose plain default-grid form is invariant and so depend on a free position to break it); and (b) no two letters may share a silhouette, since detection/segmentation/OBB see only the filled shape — `d` and `o` were once pixel-identical rounded rectangles, caught now by `test_no_two_letters_share_a_silhouette`. That check compares letters upright, so `test_no_two_letters_share_a_silhouette_at_any_angle` sweeps relative rotations as well — the generator draws every object turned, and a pair that coincides at some angle is exactly as unlearnable. Two did: an upside-down `v` was `a` with the crossbar removed (0.85), and an upside-down `t` was `i` missing a serif (0.82). Fix such a pair on whichever letter can afford it — `t` dropping its crossbar to lowercase height separates that pair too, but a thin cross's hull is nearly a diamond, whose minimum-area box is flush to a side, so every crossed `t` leaned 15–22 degrees and failed the uprightness rule above; widening `i`'s serifs cost nothing. Worst remaining pair is `c`/`g` at 0.80, upright.
- A letterform must also be shaped so its **minimum-area OBB comes out upright** — flush to the letter's own axes rather than leaning across it. `polygon_to_obb` returns the true minimum-area box, so a hull dominated by one long diagonal gets a box tilted along that diagonal: correct by definition, and plainly wrong in an `--task obb` preview, where the box stops reading as "this letter, rotated". `j` was exactly that — a bare hook whose hull ran from the stem top to the far side of the hook, giving a box 39.6 degrees off the stem to save 6% of the area; its top bar fills that corner so the upright box wins outright. `test_letter_obb_stays_upright` pins it. Fix a failure in `letters.json`, never with a tie-break or an axis-aligned preference in `polygon_to_obb` — that would break `SymbolShape.ARROW`'s genuinely diamond OBB. `q` had the same defect milder — its tail reached far enough to the lower right to lean the box 11.2 degrees — and was fixed by steepening the tail so it lengthens the letter instead of widening it. That is the general shape of the fix: a spur should extend the letter along an axis it already occupies, not diagonally away from it. No letter is exempt; `s`'s 1.4 degrees is the largest lean the family carries, and it is a floor rather than an oversight — an `s` is two loops opening in opposite directions, so its widest points are inherently diagonal to each other, and the only way further down is to flatten the curves that make it an `s`. Balancing each loop horizontally (so neither reaches further to its own side than the other does) is what took it there. Note this uprightness rule is a *letters* rule, not a package-wide one — an animal or symbol's canonical pose leans wherever its silhouette says it does (`arrow` 42 degrees by documented intent, `rabbit` 37.5, `kite` 39.8), and reshaping traced artwork to force an upright box would distort the animal.
- The package-wide OBB guarantee is **pose recovery**, checked by placing the shape back: take a shape's upright reference outline, turn and scale and place it by nothing but the four OBB corners, and it must land back on the drawn object. `tests/test_unit/test_data/_obb_pose.py` holds the rebuild; `test_geometry.py` runs it over all 49 shapes at seven angles and `test_generator.py` over what the generator actually exports. Read the rotation *relative to the shape's own reference box* rather than from the raw corner angle — a canonical pose need not be axis-aligned (see above) — and accept any of the four quarter turns, since a box is unchanged by a half turn and a square one by a quarter turn. This is what catches a tie-break that flips between equal-area candidates as a shape spins, a hull whose vertex set shifts under rotation, and any drift between a polygon and the box derived from it; the older `test_obb_is_rotation_equivariant` checks the box's corners as an unordered set and cannot see a shape rebuilt onto the wrong pose.
- A `LetterShape` outline must stay one single, simple (non-self-intersecting) polygon — never a disjoint pile of stroke ribbons — since a detector trained on several disconnected blobs under one class label learns an ambiguous object. A letter with an enclosed counter (`a`, `b`, `d`, `o`, `p`, `q`, `r`) therefore needs exactly one `letters.json` `cuts` entry per independent cycle in its stroke graph (two for `b`, which has two bowls) — the count must equal the graph's own cycle rank (`edges - nodes + connected_components`), checked by `test_counter_letter_cut_count_equals_its_cycle_rank`. Naming too few cuts leaves an un-opened counter, which `_stroke_outline` catches by tracing more than one face and raising, rather than silently producing a multi-ring shape. The hairline slit a cut leaves is the one documented place a skeleton edge leaves the fill; keep `LETTER_COUNTER_GAP` far below `LETTER_STROKE_WIDTH`, both so the slit stays invisible and because two round caps that close together would overlap and self-intersect the ring (which is why cut stubs alone cap flat).
